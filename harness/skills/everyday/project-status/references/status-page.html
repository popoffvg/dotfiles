Snapshots: where the project stands

A snapshot freezes a Platforma instance inside its own storage bucket. Later we can restore the instance from that bucket alone, and every file the restored database needs is still there. Today the daily database dump does not match the files: cleanup deletes files after the dump, so a restore can point to files that are gone.

What the project gives, in plain words

Snapshot

A frozen copy point of one instance: its database and the work files it needs, kept in the bucket. Made before an update, or on a schedule.

Restore

Brings an instance back from a snapshot, also on new infrastructure. It always gets a new instance id, so nothing mixes with the old one.

Generation

A folder in the bucket for the files written between two snapshots. A snapshot closes one generation and starts the next, so old files never change.

Deletion guardrail

While a snapshot is copied, file deletes wait. Nothing the snapshot needs can disappear during the copy.

Housekeeper

Cleans the bucket: deletes the files that no snapshot and no instance needs. It runs in dry-run mode first.

Migration

Moves existing customer instances to the new layout at their first start on the new version.

What slows the project

Waiting for review

  • Two finished pull requests (#2506, #2507) waited 8 days for review, from 18 to 26 November.
  • Big pull requests wait longer: 3.8 days for 1,500+ added lines, 0.7 days under 500 lines.
  • 7 parts of the remaining work run one after another. Each extra working day of review wait per part moves the end date by about 7 working days.

Ask: review each snapshots pull request within 1 working day.

CI failures not caused by this work

  • To keep the work moving, the project opened 5 extra CI pull requests: slow-test labels (#2317), turn off the minio tests (#2319), the k8s test timeout (#2443), k8s log rotation (#2354), and a filter for the driver block tests (#2505, still open).
  • The k8s test timeout became its own task, MILAB-7322.

Ask: an owner for the k8s and quality-gate checks, so a red check does not block a finished pull request.

Other work in parallel

  • 63% of my Platforma work time went to this project. The other 37% went to other tasks: storage notification fixes, a before-delete notification fix, CI workflow changes, a get-field performance check, and reviews.
  • The share changed by week: 94%, 74%, 39%, 62%, 46%.
  • On 10, 20, and 24 November other tasks took the whole day.

The "last month's focus" dates assume the same share as last month.
