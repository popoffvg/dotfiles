# wm — leading words

The shared taxonomy. One word, one meaning, used verbatim by all five skills — `code` (the router),
`arch` (design), `impl` (source and git history), `review` (judging code), `teach` (the human's
understanding). A word used in two of them is defined here once; a word private to one skill is
defined there.

Not the project's ubiquitous language — that lives in the notes-dir `GLOSSARY.md`
(example: `arch:examples/glossary.md`).

| Word | Meaning |
|------|---------|
| **the gate** | The human-review checkpoint between spec and TODOs. `new` produces a reviewable spec + its ADRs and **stops**; a human reads it; only then `todo` authors bodies. Authoring TODOs before the gate turns a wrong spec into wrong code — the mistake the gate exists to prevent. |
| **ADR** | One recorded decision with its why — `<notes-dir>/adr/NNNN-slug.md`, written with the `adr` skill (wm keys: `arch:ref-adr-format.md`). Its `kind` is `architecture`, `feature`, or `implementation` (one TODO, `todo: TODO-N`). Its Properties are the rules code obeys. Read the index first and open only the ADRs it points at — `~/.claude/scripts/wm-adr-index.py`. The spec compiles from ADRs; every TODO traces back to them. A fact is not an ADR: it lives in the research artifact that established it. Rule: fix the ADR before the code, or the code drifts back. |
| **open question** | One `## <slug>` section of `<notes-dir>/QUESTIONS.md` — a choice nobody has made yet, or a choice made without a reason ("Why A over B?"). Never an ADR and never a `spec.md` section. It generates no rule and it blocks readiness. A strategic answer becomes an ADR, written after the human approves it; a tactical answer lands where it applies (spec, TODO, or `PATTERNS.md`); then the section is deleted (`arch:ref-adr-format.md` § An open question is a section of QUESTIONS.md). List them: `~/.claude/scripts/wm-open-questions.sh <notes-dir>`. |
| **target picture** | `spec.md` — what the world looks like when the work is done. Description + Goal say what is true; `adr/` + GLOSSARY.md let a human validate the model; the ledger enumerates the steps there and the Plan groups them into waves. |
| **wave** | A set of TODOs runnable at once: no `depends_on` edge between them and disjoint **Files** sets. The `## Plan` wave table is the execution order; `Ln` layers only prove the edges are legal. Widest wave first — a one-TODO-per-wave chain is a serialized spec. |
| **constraints** | The settled decisions an increment can violate, **generated** on demand from the Properties of the `adr/` ADRs, one rule `ADR-NNNN/Pn` per Property — no hand-written file holds them, and no TODO file carries a rule or the command that prints them — `todos/CLAUDE.md` names it once — so a decision that changes is edited once: in its ADR. Not part of the gate read — the human settled these decisions during the **grill**, so re-reading them at the gate checks nothing; what matters is whether an increment violates one, which `verify` audits and the review gate re-derives from the diff. Rules and what generates a row: `arch:ref-todo-sections.md` § Constraints. |
| **outcome** | A TODO's post-condition in use-case language — `<actor> can <capability>`, GLOSSARY.md terms only, no implementation nouns. The discussion object: the user aligns on outcomes at the gate before any body exists. |
| **components** | The `## Components` tree in a TODO's **human half** — one tree per package, the package path as the root carrying `# OWNS`, and under it every symbol the TODO touches, each commented `<touch> · <brick> · <part> — <role>`, exactly one marked `main` (the one carrying the Outcome's behavior). A child of a component is one member the TODO decides. The last link of the **verification chain** that names symbols, so it states the change's whole reach for a human who never opens the agent half. It is also the map `## Increments` walks: every component is named by at least one **increment**. Symbols, not paths — paths live in the agent half's **Files**. |
| **touch** | What a TODO does to one component: `create`, `modify`, or `delete`. It types the symbol, not the file — a created component may land in a file **Files** marks `modify`. A component the TODO only reads is untouched and belongs in **Pre-reads**. |
| **brick** | The type of a component — what responsibility it owns. A closed set: `command`, `service`, `flow`, `gateway` (driver, repository), `server` / `consumer`, `policy`, `scheduler`, `wiring`. Each carries a **metric** (one number counted in the finished code) and a common structure; roster: the `arch` skill. A component that fits no brick, or fits two, owns more than one responsibility — split it. |
| **increment** | One H3 in the `## Increments` sequence of a TODO's **human half** — the smallest step worth approving on its own, and self-contained for review: its block alone carries a **summary** of one to three sentences (before and after, when it changes behavior), a **Surprises** list of the details a reader would otherwise find only in the code, and the **Surface** diff it lands. It changes one component only; a caller in another component moves in an increment of its own. It names symbols, never a file: its paths are in the agent half's **Files**, keyed by increment number. Increments are ordered deepest-first; a broken build lasts one increment, until the migration increment that follows it in the same commit. Numbered `<c>.<i>` — commit, then increment. They split the *review*; the `### Commit` sections split the *history*: increment `c.1` creates commit `c`, each later approved increment `c.i` is appended to it, and at each commit the repo builds and the tests pass. The human approves each one at the gate as a prediction, and again at `impl` against the real diff, as often as the **approve** key asks. A rejected increment stops the TODO. |
| **pair** | The two files one ledger row compiles to: `todos/TODO-N.md`, the human's gate read (Outcome, New terms, Components, **Flow changes**, **Increments** — each with its own diff, grouped into commits by `### Commit` sections; ≤ 200 lines of prose, carrying the `status`), and `todos/TODO-N.agent.md`, the implementer's (Files — each path keyed to its increments — Pre-reads, Manual test, Gotchas — the traps the implementer found, kept for the next session; no line budget, no frontmatter). Split by audience, not by size. Self-contained means the pair plus the generated rule set is enough; neither half restates the other, and each carries one link to the other. Written in two stages — the human half (increments included) and the test file first, the agent half only after the human approves them; renumbered and deleted together. |
| **surface** | What a caller of the changed code can see: types, fields, method and function signatures, and settings with their real values. Each **increment** in a TODO's **human half** carries the surface it lands as one **Surface** diff, so the whole contract change is split across the increments and names no file. The agent half carries no diff at all. Its opposite is a **body** — a function body, loop, branch chain, shell script, query, regex, fixture, or literal expected-value table — which never appears in a diff, because a body written in a TODO is written twice: the implementer either copies it (the review happened against a paste) or improves it (the TODO is wrong from the first commit). A body's decisions go in the increment's **Surprises**, and its steps in `## Flow changes`; an increment whose deliverable is *only* a body carries a plain contract block as its **Surface** instead of a diff. Never put a function body in the diff — the sole exception is a body **the human asks for directly**, marked with a `**Body requested:**` bullet naming the symbol. |
| **compile floor** | The smallest surface that still leaves the repo compiling. When one increment's **Surface** diff cannot fit the 150-changed-line budget — a Go interface needing every method at once, say — it takes the extra lines and declares a `**Compile floor:**` bullet under that diff. The repo building is an invariant; the budget is not. |
| **blast radius** | The **predicted** reach of a mistake — the symbols, callers, and consumers it forces you to retest. The **reach** question of **risk**; the callers one **increment** breaks are in its **Surprises**. Reach, never effort: a one-line edit to a shared type outreaches a large isolated module. |
| **risk** | The TODO frontmatter key `red \| yellow \| green` — the worst answer to three questions: **reach** (the blast radius), **flow** (does it break a step of the **main user flow**), **recovery** (does the user have a backdoor, or can they wait). The single source, with what each color changes, is `arch:examples/todo.md`. |
| **main user flow** | The steps a user MUST pass to get the main result of the product — the flow marked `main` in `<notes-dir>/workflows/flows.json`. Owner: `dive:sub-workflow.md` § Rules — `flows.json`. |
| **size** | The PR one TODO becomes, banded `S`, `M`, or `L` in the human half's frontmatter (`size`). Work and reading time, not reach — the opposite axis to **blast radius**, so a one-line edit to a core type is `risk: 5, size: S`. Two counts set it and the wider one wins: the paths in the agent half's `## Files` (S ≤ 3, M ≤ 8) and the **increment**s (S ≤ 3, M ≤ 6). `spec-lint` B12 recomputes the letter from the pair. An `L` row is asked about before it is written — the usual answer is two ledger rows. |
| **ledger** | The TODO List in spec.md — an index of outcomes — one `#### TODO-N` entry each, with `Layer` / `Outcome` / `Commit` lines, no bodies. |
| **status** | The lifecycle phase carried in YAML frontmatter — never body prose. Two machines: the spec's `init → review → impl` (`spec.md`) and each TODO's `todo → impl → verify → done` (`blocked` off the path). The single source is `arch:ref-write.md` § Status. |
| **approve** | The frontmatter key saying how much of `impl` the human reviews: `increment` (a diff after every **increment**), `todo` (one diff per TODO), `none` (no stop — the review gates are the only check). It sits at two levels — `spec.md` for every TODO the spec drives, `todos/TODO-N.md` for one TODO — and the TODO wins. The TODO also takes `inherit`, meaning the spec's value; a missing key reads as `inherit` on a TODO and as `increment` on a spec. Written by `new` Step 0.6 and by `todo` per row, read by `impl` Step 5; `auto` runs as `none` whatever either says. It never lowers a hard gate. The single source is `arch:ref-write.md` § Approval. |
| **grill** | The depth-first interview loop that drives the open questions to zero. One question at a time; a strategic answer becomes an ADR, a tactical one lands where it applies, and each deletes its section of `QUESTIONS.md`; spec updated inline. |
| **trace** | (1) The one-sentence entry→exit path — the `// trace:` line opening a `flow`, which must match the TODO's Outcome. (2) The ADRs read backward from an artifact to the decision that produced it, along their markdown links and changelogs, with their `Superseded by` lines. It is **walked, never stored**: no file under `todos/` carries an origin link, so nothing can go stale. Run the `trace` skill (`wm:trace`) with the artifact quoted; it searches `adr/` in a `tracer` subagent and returns at most 8 chain rows plus a verdict — `live`, `superseded`, or `unrecorded`. |
| **layer (Ln)** | Call-sequence depth. TODOs land deepest-first: `L0` leaf (talks to the outside world) → `Lmax` wiring (`main.go`). A leaf commit compiles alone; upper layers never rewrite it. |
| **verification chain** | Type → Outcome → New terms → Components → Flow changes → Increments → Autotest → Commits. A human approves a TODO by walking the chain top-down through `TODO-N.md` and `TODO-N.test.md`, repo closed and the agent half shut; each link is checked against the Outcome, the anchor. `Components` names the symbols and `Increments` show the steps and what each symbol becomes; the two are one pair, since a list of names without shapes approves a rename and a diff without reach approves an unbounded change. Each increment is checked again at `impl`: against the real diff rather than a prediction, at the grain the **approve** key sets. |
| **audit** | `verify` — adversarial, read-only, run in a separate `spec-verifier` agent that did not write the spec. Hunts contradictions, missing parts, edge cases. A finding without a reproducing scenario is a nit, not a blocker. |
| **drift** | Divergence between two things that should match: shipped code vs its spec (`revise` settles it), or a stale doc vs reality (sediment — fix in place). |
| **deviation** | Drift the user chose on purpose during `impl`: a correction to a shown diff that contradicts the pair and stays inside one TODO. It ships, and one row in `TODO-N.md` `## Deviations` names the section it contradicts, plus the `kind: implementation` ADR holding the reason. The approved sections stay as the human read them; `revise` folds the rows back in and deletes the section. A correction reaching past the TODO is not a deviation — it routes to `revise` (`impl:sub-impl.md` § When a correction contradicts the pair). |
| **notes-dir** | `<notes-dir>` (commonly `.notes/`) — the wm notes directory, its own jj repo, git-ignored in the parent. Resolve it from the active phase; never hardcode `_notes/` or `.notes/`. |
| **mutant** | One small behavior-changing edit to shipped source, written to test the tests: **killed** when a covering test fails under it, **survived** when they all still pass, **equivalent** when no test could ever kill it because nothing observable changed. A survivor is a missing assertion, never a mutant to drop. The operator roster and the equivalent rows are the `mutation` skill; the `mutation` gate of `review:ref-gates.md` runs it. |
| **fixup** | `git commit --fixup=<sha>` recording a user correction. The fixup trail is what `squash` reads to distill lessons; a correction folded into a normal commit is a lost lesson. |
