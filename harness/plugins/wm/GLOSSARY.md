# wm — leading words

The shared taxonomy. One word, one meaning, used verbatim by all four skills — `code` (the router),
`arch` (design), `impl` (source and git history), `teach` (the human's understanding). A word used
in two of them is defined here once; a word private to one skill is defined there.

Not the project's ubiquitous language — that lives in the notes-dir `GLOSSARY.md`
(template: `arch:tpl-glossary.md`).

| Word | Meaning |
|------|---------|
| **the gate** | The human-review checkpoint between spec and TODOs. `new` produces a reviewable spec + thought graph and **stops**; a human reads it; only then `todo` authors bodies. Authoring TODOs before the gate turns a wrong spec into wrong code — the mistake the gate exists to prevent. |
| **thought** | The atom of reasoning — one recorded decision/fact with its why (concept + rules: the `thought` skill). Here it is a standalone note in `thoughts/` — `question`, `decision`, `fact`, or `impl-decision` (format: `arch:ref-note-format.md`). Every note carries a 1–3 sentence `description`; read the index first and open only the notes it points at — `~/.claude/scripts/wm-thought-index.py`. The spec compiles from thoughts; every TODO traces back to them. Rule: fix the thought before the code, or the code drifts back. |
| **open question** | An unresolved thought — `thoughts/NNN-question-*.md` with `status: open`. Never a `spec.md` section. It blocks readiness until a new `decision` or `fact` note answers it, which archives the question (`arch:ref-note-format.md` § Resolution). List them: `~/.claude/scripts/wm-open-questions.sh`. |
| **target picture** | `spec.md` — what the world looks like when the work is done. Description + Goal say what is true; `thoughts/` + GLOSSARY.md let a human validate the model; the ledger enumerates the steps there and the Plan groups them into waves. |
| **wave** | A set of TODOs runnable at once: no `depends_on` edge between them and disjoint **Files** sets. The `## Plan` wave table is the execution order; `Ln` layers only prove the edges are legal. Widest wave first — a one-TODO-per-wave chain is a serialized spec. |
| **constraints** | The `## Constraints` table in a TODO's **agent half**, above the increments it bounds — every settled decision an increment can violate, restated as the rule only and carrying a `C<n>` id, one row per decision. It exists so the pair is self-contained: the implementer never opens `spec.md` or a note. Where each rule came from is one `Constraints: C<n>` row in the **trace**, never a column here. Not part of the gate read — the human settled these decisions during the **grill**, so re-reading them at the gate checks nothing; what matters is whether an increment violates one, which `verify` audits and the review gate re-derives from the diff. |
| **outcome** | A TODO's post-condition in use-case language — `<actor> can <capability>`, GLOSSARY.md terms only, no implementation nouns. The discussion object: the user aligns on outcomes at the gate before any body exists. |
| **components** | The `## Components` table in a TODO's **human half** — the `package.Class` symbols it touches, each carrying a **touch** (`create | modify | delete`), its **brick**, and a one-sentence role, exactly one marked `main` (the one carrying the Outcome's behavior). The last link of the **verification chain** that names symbols, so it states the change's whole reach for a human who never opens the agent half. It is also the map `## Changes` walks: every row is named by at least one **increment**. Symbols, not paths — paths live in the agent half's **Files**. |
| **touch** | What a TODO does to one component: `create`, `modify`, or `delete`. It types the symbol, not the file — a created component may land in a file **Files** marks `modify`. A component the TODO only reads is untouched and belongs in **Pre-reads**. |
| **brick** | The type of a component — what responsibility it owns. A closed set: `command`, `service`, `flow`, `gateway` (driver, repository), `server` / `consumer`, `policy`, `scheduler`, `wiring`. Each carries a **metric** (one number counted in the finished code) and a common structure; roster: the `arch` skill. A component that fits no brick, or fits two, owns more than one responsibility — split it. |
| **increment** | One entry in the `## Changes` sequence of a TODO's **agent half** — the smallest step worth approving on its own, carrying **Files**, a **Surface** bullet naming the symbols it lands, a **Do** of one to four imperative sentences, and a predicted **blast radius**. It states *what to do*, never a diff: the diff lives once in the human half's `## Surface`. Increments are ordered deepest-first so the repo builds after each. They split the *review*, not the deliverable: increment 1 creates the commit and each later approved increment is appended to that same commit. Approval happens at `impl`, one increment at a time against the real diff. A rejected increment stops the TODO. |
| **pair** | The two files one ledger row compiles to: `todos/TODO-N.md`, the human's gate read (Outcome, New terms, Components, **Surface** — the one diff — Autotest, Commit; ≤ 550 lines, carrying the `status`), and `todos/TODO-N.agent.md`, the implementer's (Constraints, Changes — the increments described, no diff — Files, Pre-reads, Manual test, Definition of done; no line budget, no frontmatter). Split by audience, not by size. Self-contained means the pair is enough; neither half restates the other, and each carries one link to the other. Written, renumbered, and deleted together. |
| **surface** | What a caller of the changed code can see: types, fields, method and function signatures, and settings with their real values. It has its own section — `## Surface` in a TODO's **human half**, the one diff in the pair, holding the whole contract change one ```diff per file. The agent half carries no diff at all. Its opposite is a **body** — a function body, loop, branch chain, shell script, query, regex, fixture, or literal expected-value table — which never appears in a diff, because a body written in a TODO is written twice: the implementer either copies it (the review happened against a paste) or improves it (the TODO is wrong from the first commit). A body's logic goes in **Behavior** as pseudocode; a file that is *only* a body carries a plain contract block in `## Surface` instead of a diff. Never put a function body in the diff — the sole exception is a body **the human asks for directly**, marked with a `**Body requested:**` bullet naming the symbol. |
| **compile floor** | The smallest surface that still leaves the repo compiling. When one file's `## Surface` diff cannot fit the 150-changed-line budget — a Go interface needing every method at once, say — it takes the extra lines and declares a `**Compile floor:**` bullet under that diff. The repo building is an invariant; the budget is not. |
| **blast radius** | The **predicted** reach of a mistake — the symbols, callers, and consumers it forces you to retest. Scored 1–5 per TODO (frontmatter `risk`) and named per **increment** (the concrete symbols). Reach, never effort: a one-line edit to a shared type outreaches a large isolated module. |
| **ledger** | The TODO List in spec.md — an index of outcomes — one `#### TODO-N` entry each, with `Layer` / `Outcome` / `Commit` lines, no bodies. |
| **status** | The lifecycle phase carried in YAML frontmatter — never body prose. Two machines: the spec's `init → review → impl` (`spec.md`) and each TODO's `todo → impl → verify → done` (`blocked` off the path). The single source is `arch:ref-write.md` § Status. |
| **grill** | The depth-first interview loop that drives the open questions to zero. One question at a time; each answer is written as a new decision/fact note and archives the question it answered; spec updated inline. |
| **trace** | (1) The one-sentence entry→exit path — the `// trace:` line opening a `flow`, which must match the TODO's Outcome. (2) The thought graph read backward (`Depends on`) and forward (`Affects`) from a decision to its why — and, written down for one ledger row, the pair's companion file `todos/TODO-N.trace.md`: one row per decision behind the pair, each anchored where it lands (`Outcome`, `Constraints: C<n>`, `Surface: <symbol>`, …) and cited to a live `thoughts/` note or a dated document. Format: `arch:tpl-todo-trace.md`; rules: `arch:sub-todo.md` § Trace. |
| **layer (Ln)** | Call-sequence depth. TODOs land deepest-first: `L0` leaf (talks to the outside world) → `Lmax` wiring (`main.go`). A leaf commit compiles alone; upper layers never rewrite it. |
| **verification chain** | Type → Outcome → New terms → Components → Surface → Autotest → Commit. A human approves a TODO by walking the chain top-down through `TODO-N.md` alone, repo closed and the agent half shut; each link is checked against the Outcome, the anchor. `Components` names the symbols and `Surface` shows what each becomes; the two are one pair, since a list of names without shapes approves a rename and a diff without reach approves an unbounded change. The eighth link, `Changes`, is checked at `impl` instead: one increment per approval, against the real diff rather than a prediction. |
| **audit** | `verify` — adversarial, read-only, run in a separate `spec-verifier` agent that did not write the spec. Hunts contradictions, missing parts, edge cases. A finding without a reproducing scenario is a nit, not a blocker. |
| **drift** | Divergence between two things that should match: shipped code vs its spec (`revise` settles it), or a stale doc vs reality (sediment — fix in place). |
| **notes-dir** | `<notes-dir>` (commonly `.notes/`) — the wm notes directory, its own jj repo, git-ignored in the parent. Resolve it from the active phase; never hardcode `_notes/` or `.notes/`. |
| **fixup** | `git commit --fixup=<sha>` recording a user correction. The fixup trail is what `squash` reads to distill lessons; a correction folded into a normal commit is a lost lesson. |
