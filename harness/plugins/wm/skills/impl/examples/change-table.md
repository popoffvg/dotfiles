# impl — the change table

> Two filled artifacts: the table shown above one increment's diff, and the table shown once over a
> whole TODO. Copy the one the resolved `approve` key asks for, replace the content, delete the `>`
> lines — each one states the rules for the piece above it.
> The nine kinds a row's Kind column takes, the scale each table belongs to, and where each one is
> shown are `ref-change-types.md`.

## Above one increment's diff — `approve: increment`

```
Increment 3 — thread the run id to the column writer

| Kind                | File | What |
|---|---|---|
| new behavior        | writer/column.py:41 | stamp `run_id` into every written column spec |
| signature change    | writer/column.py:12 | `write_columns(specs)` → `write_columns(specs, run_id)` |
| wiring              | cli/export.py:88 | pass the parsed `run_id` down to `write_columns` |
| call-site migration | tests/test_column.py:20,54 | migrate two calls to the new parameter |

Blast radius predicted: writer/column.py, cli/export.py — real diff matches.
```

> The heading is the increment's number and its title from `TODO-N.agent.md` § Changes, verbatim.
>
> **One row per changed file**, `new behavior` and `signature change` rows first — those are the rows
> the human reads line by line, and putting them at the top is what makes the rest a skim. A file
> carrying two kinds gets two rows.
>
> **Every changed file has a row.** A file in the real diff with no row is the table's one fatal
> error: the human approves what the table shows, so an unrowed file is a diff nobody read.
>
> **`File` is the repo-relative `path:line`** where that file's change starts — the declaration line
> for a `signature change`, the first changed line otherwise. Several lines in one file join after a
> single path, comma-separated and ascending: `tests/test_column.py:20,54`.
>
> **`What` completes the sentence "the diff …"** — one present-tense clause, verb first, ≤ 12 words,
> naming the symbol it acts on: *stamp `run_id` into every written column spec*, *migrate two calls
> to the new parameter*. Two shapes are the exception, because in those rows the change *is* the
> shape: a `signature change` writes `<old> → <new>`, and a `generated` file names the tool that
> rewrote it (*regenerated by `mise run harness:plugins:sync`*) — the human is told not to read that
> file, so a `What` written for them to read is a `What` that misleads.
>
> **A `new behavior` row belongs to the file that decides.** A file that only forwards a value it
> does not compute, default, or store is `wiring`, whichever layer it sits in; typed `new behavior`
> it sends the human to read a diff that decides nothing, and hides the file that does.
>
> **The table closes with the blast-radius line:** `Blast radius predicted: <the files the
> increment's **Blast radius** bullet named> — real diff matches.` It is required, and it is where
> the human learns the plan held. When the real diff went outside that set, say so instead —
> `— real diff also touched cli/parse.py` — which is the signal the plan is wrong
> (`impl:sub-impl.md` step 5.3), not a line to quietly rewrite.

## Once over the whole TODO — `approve: todo` and `approve: none`

```
TODO 4 — stamp exports with the run they came from

| Kind              | File | What |
|---|---|---|
| new behavior      | writer/column.py:41 ← start point | stamp `run_id` into every written column spec |
| signature change  | writer/column.py:12 | `write_columns(specs)` → `write_columns(specs, run_id)` |
| signature change  | cli/export.py:71 | `export(path)` → `export(path, run_id)` |
| the rest, counted | — | 3 wiring, 11 call-site migrations, 1 generated |
```

> The heading is the TODO's number and its ledger Outcome in the human's words.
>
> **Same columns, same rules, one fewer row set.** It carries every `new behavior` and
> `signature change` row, ordered outward from the start point along the calls, and no others.
>
> **The start point is marked in its own row** — `← start point` after the path. It is the one
> `file:line` where the new behavior begins, the deepest `new behavior` row that no other changed
> symbol calls, and it is the first thing the human opens.
>
> **`the rest, counted` is one row, `File` is `—`, and `What` counts every remaining kind that has at
> least one file**, in the order `ref-change-types.md` § The roster lists them: wiring, call-site
> migration, rename, move, deletion, test, generated. A kind with no file is left out, not written as
> `0`. Name the files behind the row only when the human asks.
>
> **No blast-radius line here.** The whole-TODO diff is shown next to the **Blast radius** of every
> increment in it, so a per-table prediction has nothing left to add.
