# impl — the change table

> Two filled artifacts: the table shown above one increment's diff, and the table shown once over a
> whole TODO. Copy the one the resolved `approve` key asks for, replace the content, delete the `>`
> lines — each one states the rules for the piece above it.
> The nine kinds a row's Kind column takes, the scale each table belongs to, and where each one is
> shown are `ref-change-types.md`.

## Above one increment's diff — `approve: increment`

```
Increment 3 — thread the run id to the column writer

| Kind                | What |
|---|---|
| new behavior        | stamp `run_id` into every written column spec |
| signature change    | `write_columns(specs)` → `write_columns(specs, run_id)` |
| wiring              | pass the parsed `run_id` down to `write_columns` |
| call-site migration | migrate two calls to the new parameter |

Blast radius predicted: `write_columns`, `export` — real diff matches.
```

> The heading is the increment's number and its title from `TODO-N.md` § Increments, verbatim.
>
> **A subagent writes this table** (`sub-impl.md` step 5.3). It finds each change in the diff and
> assigns one kind from `ref-change-types.md`. The session shows the table it returns.
>
> **One row per change**, `new behavior` and `signature change` rows first — those are the rows
> the human reads line by line, and putting them at the top is what makes the rest a skim. A change
> has one kind. Two kinds are two rows.
>
> **Every change in the diff has a row.** A change with no row is a diff nobody classified: the
> human approves what the table shows.
>
> **`What` completes the sentence "the diff …"** — one present-tense clause, verb first, ≤ 12 words,
> naming the symbol it acts on: *stamp `run_id` into every written column spec*, *migrate two calls
> to the new parameter*. Two shapes are the exception, because in those rows the change *is* the
> shape: a `signature change` writes `<old> → <new>`, and a `generated` change names the tool that
> wrote it (*regenerated by `mise run harness:plugins:sync`*). The place the change lives is the
> diff under the table. The subagent found it; the row does not repeat it.
>
> **A `new behavior` row is the change that decides.** A change that only forwards a value it does
> not compute, default, or store is `wiring`. Typed `new behavior`, it sends the human to read a
> diff that decides nothing, and hides the change that does.
>
> **The table closes with the blast-radius line:** `Blast radius predicted: <the symbols the
> increment's **Blast radius** bullet named> — real diff matches.` It is required, and it is where
> the human learns the plan held. When the real diff changed a symbol outside that set, say so
> instead — `— real diff also changed `parse`` — which is the signal the plan is wrong
> (`impl:sub-impl.md` step 5.3), not a line to quietly rewrite.

## Once over the whole TODO — `approve: todo` and `approve: none`

```
TODO 4 — stamp exports with the run they came from

| Kind              | What |
|---|---|
| new behavior      | stamp `run_id` into every written column spec ← start point |
| signature change  | `write_columns(specs)` → `write_columns(specs, run_id)` |
| signature change  | `export(path)` → `export(path, run_id)` |
| the rest, counted | 1 generated, 11 call-site migrations, 3 wiring |
```

> The heading is the TODO's number and its ledger Outcome in the human's words.
>
> **Same columns, same author, one fewer row set.** That subagent writes it over the whole diff.
> The table carries every `new behavior` and `signature change` row, ordered outward from the
> start point along the calls, and no others.
>
> **The start point is marked on its own row** — `← start point` at the end of `What`. It is the
> deepest `new behavior` change that no other changed symbol calls, and it is the first change the
> human opens in the diff.
>
> **`the rest, counted` is one row, and `What` counts every remaining kind that has at least one
> change**, in roster order, skipping `new behavior` and `signature change`. A kind with no change
> is left out, not written as `0`. Name the symbols behind the row only when the human asks.
>
> **No blast-radius line here.** The whole-TODO diff is shown next to the **Blast radius** of every
> increment in it, so a per-table prediction has nothing left to add.
