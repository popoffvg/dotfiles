# Launch a background spec revision

1. **Bound the request.** Resolve the absolute notes directory, target TODO or spec scope, and the user's exact corrections. Include supplied commit references, deviations, and prior approvals. Ask for missing scope before launch. Check the caller's active tasks for writers in that directory and await their completion. If another session might write there, ask the user to confirm exclusive access before launch.
2. **Prepare the fix brief in Opus.** If the caller is not Opus, ask the user to switch to Opus before proceeding. The calling Opus session owns diagnosis and correction decisions. Name each changed fact, its canonical source, stale target sections, intended replacement, and acceptance check. Include prior approvals. Settle open decisions with the user before delegation; leave file edits to Sonnet.
3. **Launch once.** Read `${CLAUDE_PLUGIN_ROOT}/agents/spec-reviser.md`. Start `Agent` with `subagent_type: "wm:spec-reviser"`, `model: "sonnet"`, and `run_in_background: true`. Use a fresh agent, not a fork. Pass a self-contained prompt with the fix brief, absolute notes directory, absolute plugin root, and report path `<notes-dir>/revision-report.md`.
4. **Return control.** Report the agent ID, selected model, notes directory, and report path. Keep that directory free of concurrent edits until completion. Use the completion notification rather than polling.
5. **Collect in Opus.** Read the report after completion and check it against the fix brief. Report completed changes or the exact blocker. Settle new decisions or approval questions with the user before sending a corrected brief to Sonnet.
